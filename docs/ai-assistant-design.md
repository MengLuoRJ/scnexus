# 本地 智能助手与 MCP 服务

## 目标与首期范围

提供独立于账号、官方服务及工坊的本机 MCP 服务。功能默认关闭；启用后侧栏显示“智能助手”，玩家在专用页面手动启动服务。应用重启不自动监听。首期只读能力现扩展为受控战役操作与突变查询，不提供任意命令、任意文件读取、任意 IPC 或远程代理。

## 实现边界

- main 使用官方 TypeScript MCP SDK 与 Node HTTP 的 Streamable HTTP 无状态传输；SDK 负责协议协商、发现和工具调用。
- HTTP 固定绑定 `127.0.0.1`，路径 `/mcp`；默认端口 17861，允许整数 1024–65535。端口冲突明确报错，不自动换端口。
- renderer 仅通过 `src/ipcs/` 控制服务；preload 暴露明确方法；共享 DTO 不包含内部服务对象。
- 工具直接复用本地业务服务，不调用页面 IPC，不复制安装或下载实现。
- 下载查询沿用已有账号可见性；官方服务关闭不影响公开 GitHub 任务读取。本地游戏未配置时返回受控状态，不能阻断 MCP 启动。

## 功能设置与生命周期

持久化 `aiAssistantEnabled=false` 与 `aiAssistantPort=17861`，配置升级为旧数据补默认值。功能开关独立于官方服务。启用只显示入口，不启动 HTTP；关闭停止服务并使连接失效。切换页面不停止服务，应用退出统一清理。

服务状态为 stopped / starting / running / stopping / error；只有监听完成才发布 running。启停串行化，失败保留安全错误码。停止必须关闭连接并释放监听端口。

## 认证与 HTTP 边界

- Token 使用 `crypto.randomBytes(32)` Base64URL，保存在 main 内存，不持久化，应用重启更换。
- 每个请求验证 Bearer Token，长度检查后恒定时间比较；不接受 URL 查询参数认证。
- 校验精确 Host，拒绝带 Origin 的网页请求，不开放宽泛 CORS；不将仅本机监听当作身份认证。
- 限制请求大小、并发和超时；停止和轮换 Token 取消旧连接。不得回显 Token、认证头或原始异常。
- 页面仅在显式显示、复制或生成配置时请求 Token，不放入 Pinia、普通设置快照或广播。
- Token 持有者可以调用查询及无冲突的战役激活/切换；恢复原版、卸载及已有激活战役的切换默认在客户端确认，用户可逐工具授予自动审批。请仅将 Token 交给可信的 AI 客户端。本机制不防御已控制用户操作系统的程序。

## 只读工具与数据最小化

首期工具：`get_app_status`、`list_campaigns`、`get_campaign_details`、`list_custom_content`、`list_downloads`、`get_task_status`。注册 schema 执行参数校验，列表限定数量，详情按已知 ID 查询。输出仅明确投影的 DTO，不返回凭据、本机绝对路径、完整文件、内部 Store 或异常堆栈。第三方内容字段作为不可信数据，不作为工具执行指令。

工具按实际行为提供 MCP 注解：查询为只读，战役操作为非只读、可能破坏性且不宣称幂等；注解不是授权机制。新增 `activate_campaign`、`switch_campaign`、`restore_campaign`、`uninstall_campaign` 只接受已知本地 id。激活/切换仅在现有预检查无冲突时直接执行；恢复表示取消激活并恢复原版，不是重新安装。未授予对应自动审批时，恢复与卸载通过可信主窗口的原生确认对话框逐次批准；无窗口、拒绝、超时、停止或轮换令牌导致确认失效时不得提交。冲突不得自动覆盖/删除，交回现有管理界面处理。确认后重新检查状态与预览，业务层继续执行既有互斥和事务保障。

新增 `list_mutators`（可按名称或 id 搜索并分页）和 `get_weekly_mutation`（CN/NA/EU/AS，支持六种资料语言），复用本地数据与规则；总开关和校准开关都开启才请求后端校准，后端失败保留本地结果，不要求登录。

已有同类别战役时，`switch_campaign` 默认使用一次明确列出当前战役和目标战役的确认（对应自动审批开启时免确认），先恢复再激活；两个步骤不是原子操作，第二步失败或取消返回 `partially-completed` 和已停用战役 ID，不伪称成功。`activate_campaign` 不会擅自替换已激活战役。切换目标变更、文件清单漂移或共享资源冲突时交回人工处理。

取消仅能阻止尚未提交的写操作。一旦开始业务提交，停止服务先关闭网络入口，再等待已提交事务完成；记录保留真实成功/失败，不把网络断开误称为回滚。AI 客户端若连接断开，应重新查询战役状态，不应盲目重试。

### 逐工具持久化自动审批

MCP 能力列表为 `switch_campaign`、`restore_campaign`、`uninstall_campaign` 分别提供自动审批开关，默认关闭，互不继承。偏好保存到 main 设置，重启后有效；它们不因 MCP 重启、Token 轮换、官方服务开关而自动改变。只读查询与无需批准的激活不提供多余开关。

默认值通过设置 schema 升级为旧配置补齐 false，不继承其他审批项。验证包括开启确认/拒绝/来源失效、按工具隔离、提交前撤销、设置写 IPC 来源转交、界面订阅与失败回读。

从关闭改为开启时必须由可信客户端窗口显示主进程原生风险确认；无窗口、窗口导航、拒绝或异常不得保存授权。关闭授权无需确认。MCP 工具不提供修改这些偏好的接口。用户授权后可在无可用窗口时执行对应已批准操作，但必须继续检查请求信号、记录归属、资源哈希、文件冲突和操作前状态；提交前重新读取授权，撤销后的在途预检查不能借旧授权提交。自动审批仅免去本次确认，不是自动覆盖或强制删除。

## 控制页面与记录

“功能管理”中增加独立 AI 功能开关。专用页面显示服务状态、端口、手动启停、Token 显示/复制/重新生成及通用 HTTP 连接配置。轮换前确认旧连接失效。配置示例需按实际 AI 客户端验证，不声称一份配置适用于所有客户端。

侧栏使用现有 `Menu_Agent.png` 菜单图片。页面使用“服务配置 / MCP 能力 / 操作记录”三个标签页，默认进入服务配置，不重复标题栏标题。配置分为服务状态与连接、客户端认证两部分；切换标签不停止服务或重建订阅，离开配置时清除显示的令牌并使未完成的凭据响应失效。能力页列出当前十二项查询与受控操作及本地化说明：列表默认 20、最多 100 项，offset 为 0–100000；详情与操作的已知 id 长度为 1–200 字符；不支持任意命令或任意文件读取。以 1000×700 窗口为布局基准，能力卡片保持双列，超出高度通过页面滚动查看。

记录仅在 main 内存保留最多 500 条，退出清空，停止服务不清空。字段为 ID、工具名、执行状态、开始/完成时间与安全错误码；不保存原始参数、完整结果、Token、路径或对话。页面实时订阅，支持清空；清空历史不取消操作。查询失败使用受控提示。

## 录像复盘 AI 设计（本轮不实现）

### 状态与原则

现有 MCP 的十二项工具为应用/内容/任务查询、突变查询与受控战役操作；当前没有录像查询、录像授权或 AI 复盘实现。本轮仅记录设计，不新增模型依赖、联网调用或工具注册。跨场基础统计与游戏观看由录像模块本轮推进，不能把这两项等同于 AI 已接入。指标来源与阶段验收以 [录像分析设计](./replay-analysis-design.md) 为准。

本机 MCP 只是传输端点，连接它的 AI 客户端可能使用远程模型。Token 仅证明调用方持有凭据，既不是允许读取所有录像，也不是允许向外部模型发送数据；现有战役自动审批不继承到录像数据授权。

### 数据授权与隐私边界（待实施）

- 默认不向 MCP 暴露录像数据；由可信桌面窗口明确选择资料/分类、单场或统计时间范围、字段类别和用途，并展示将输出的结构化数据预览。列表/汇总读取也须授权，不能仅保护详情。
- 复盘授权与“外部模型发送”分别表达。连接外部模型前明确告知接收方/模型服务、发送字段、范围、聊天/身份等敏感信息及可能的远程保存策略，由用户明确授权；未知接收方不得默认为本地模型。外部 AI 客户端也需用户明确同意其数据外传行为，应用不能声称能控制第三方客户端收到数据后的再转发。
- 优先输出范围内匿名别名、必要的种族/队伍/结果及聚合数据；不返回本机路径、账号目录 ID、真实资料句柄、Token、完整录像、原始组件或全量事件流。聊天默认排除，确需使用时单独授权，玩家名、地图名和自定义文本也按可能含个人信息处理。
- 授权须有明确生命周期和撤销入口，建议默认本次服务会话有效；长期授权必须另行明确选择。主进程每次调用及返回前检查授权、范围与取消状态；资料/根目录变化、服务停止、Token 轮换或撤销使会话授权失效。具体 UI 与持久化策略仍待决策，不声称现有设置已支持。
- 撤销阻止后续读取与未交付结果，无法收回已经发送的数据，应明确告知。读取日志仅记工具、时间、范围摘要/匿名引用、授权决定及安全状态，不记录聊天、原始参数、完整结果、凭据或对话；若需扩展现有审计字段，实施时另行验证最小化与保留期。

### 只读结构化工具草案

以下名称为提案，**未注册**；沿用严格 schema、Token/Host 检查、主进程范围校验及有界查询，不能仅靠 MCP readOnly 注解授权。

| 工具                    | 有界输出与前提                                                                                                                                                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list_replays`          | 已授权范围内匿名摘要，默认20/最多100，受限筛选与分页，不接受任意文件路径或 SQL                                                                                                                                                               |
| `get_replay_summary`    | 已授权单场的已缓存 metadata/指标及各自状态、版本、覆盖和证据，不隐式触发解析                                                                                                                                                                 |
| `get_replay_statistics` | 复用主进程统计服务，不让模型重算另一套口径；返回样本/排除数和定义。当前档案/分类全部已扫描录像、不随文字搜索变化、contentHash 去重、win/(win+loss)，draw/unknown 单列；对种族仅明确1v1，地图含团队，趋势按 playedAt UTC 月份，无日期只计总数 |
| `get_replay_timeline`   | 按玩家/指标/时间窗分页的已有经济采样、生产/升级观察，保留 gameLoop，不将其称为完整建造顺序                                                                                                                                                   |
| `get_replay_evidence`   | 仅取先前结果引用的有限结构化证据，复查授权与当前内容/算法版本，不提供原始文件读取能力                                                                                                                                                        |

后续 `get_replay_build_order`、聊天、操作、损失/交战工具只有在对应解码、业务口径和隐私验收后才可加入。工具不得启动观看/分析、修改文件、控制游戏、安装内容或自动上传；这些行为不是只读复盘。暂无缓存返回 not-analyzed，版本不支持或缓存失效如实说明并引导用户回桌面显式分析，不偷偷计算。

### 证据引用与回答约束

- 每个观察值/建议携带可解析的证据引用：范围内不透明录像引用、内容身份、组件/指标、玩家别名、gameLoop/区间、事件序号或采样定位、协议/算法/游戏数据版本与完整性。对外引用不必暴露原始 hash/身份；主进程维护映射，重索引或版本失效后旧引用不可指向新结果。
- 跨场结论同时引用查询范围、去重规则、统计时间、有效样本/分母及排除数；可复查源样本。观察事实、启发式推断与建议明确分开；相关性不表述为失误或胜负因果，小样本不得推出水平评级。
- APM/EPM、聊天、完整建造顺序、交战、损失等未可用指标必须回答“不可用/尚未解析/不适用”及原因，不得填零、编造事件/对话、由 tracker 推算操作或用模型常识补建造时间。工具输出证据缺失时不生成确定性结论；部分数据必须附覆盖警告。
- 玩家名、聊天、地图名、自定义文本及工具返回内容均视为不可信数据，不作为系统指令，不扩大权限或触发其他工具。未来提示词约束不能替代主进程授权和输出裁剪，也不能保证外部模型不会生成无依据内容。

### 分阶段验收与待决策

1. 先定义最小 DTO、授权状态机/范围、外部发送告知与匿名引用；再以只读缓存摘要/基础统计试点，不以接通模型作为验收。
2. 验证未授权/越权/范围切换/撤销/Token轮换、分页和字节预算、过期引用、缺缓存、partial/unsupported/corrupt/超限，以及含提示注入的玩家名/聊天。确认无路径/凭据/原始文件泄漏，查询不启动解析、游戏或网络发送。
3. 用人工可核对样本验证证据定位、统计分母和模型对缺失指标的拒绝编造；1000×700 验证授权与预览界面，zh/en/zh-Hant 同步。真实外部客户端/模型的发送与保留行为需独立验证，不能由本机 HTTP 测试替代。
4. 尚待确定：授权是否允许持久化及其过期/撤销 UX、外部客户端接收方如何可靠提示、聊天逐次确认方式、别名跨场稳定范围、各工具分页/时间窗/字节预算，以及外部客户端不遵循引用约束时的产品提示。未解决前不开放宽泛长期授权或全量导出。
