# SC2 创作者预览工具与录像观战设计

## 1. 状态与范围

本文记录 2026-11-06 确认的产品边界和目标架构，**仅为设计，不代表包、接口、采集能力或素材已交付**。包名为实施候选，创建前核对工作区和发布名称；本轮不创建包、不安装依赖、不修改现有解析行为。

目标产出：

1. 独立模型预览器包：基于 WhiteoutLib 底层能力，TS API、数据整理、渲染与管理由本项目实现。
2. 独立地图预览器包：单独预览地图，提供 2D / 3D 模式。
3. 在现有 `@scnexus/replay-parser` 中完善精确状态的数据契约、规范化与分析能力。
4. 独立无头观战器包：消费 parser 数据，管理播放和观战分析，不依赖画布；先在客户端用文字界面验收。
5. 两个独立观战场景渲染器包：2D 与 3D，随后接入同一观战器。
6. 两个独立素材包：仅面向对战录像常用单位，分别服务 2D 与 3D；发布受授权和来源审核约束。

模型和地图预览器作为创作者工具独立提供，不以观战器完成为发布前提。浏览器性能优先，对外提供 TS API；允许底层 WASM，不将“TS API”描述成所有底层实现均为 TS。

相关约束：[应用架构](./architecture.md)、[录像架构](./replay/replay-architecture.md)、[parser 设计](./replay/replay-parser-package.md)、[第三方声明](../THIRD-PARTY-NOTICES.md)、[安全约定](../SECURITY.md)。

## 2. 产品与环境边界

| 产品             | 桌面环境                                            | 浏览器环境                                         |
| ---------------- | --------------------------------------------------- | -------------------------------------------------- |
| 模型预览器       | 拖入文件／资源目录；经用户选择读取本地 SC2 安装实例 | 仅拖入文件／资源目录，具体目录拖放能力按浏览器检测 |
| 地图预览器       | 拖入地图及依赖；经用户选择从本地安装实例补充资源    | 仅拖入地图及配套资源，缺依赖明确提示               |
| 无头观战器       | 读取受控数据源，先提供文字状态和分析                | 读取已提供的兼容观战数据，不启动游戏               |
| 2D / 3D 观战场景 | 消费同一观战状态                                    | 消费同一观战状态，满足资源与功能要求时可用         |

- 桌面允许用户选择多个 SC2 实例，资源解析绑定具体实例与版本，不隐式混合不同安装的文件。
- 拖放按集合建立虚拟资源路径；单个 M3 或地图缺少纹理／Mod 时返回缺失依赖，不伪装成完整预览。
- renderer 不直接接收任意本地绝对路径读取能力。main 提供任务／资源句柄及受控字节读取；拖入内容也由所属环境校验与授权。
- 浏览器不读取本地安装实例，不要求桌面桥接；只访问用户主动提供的拖入内容。
- GitHub 资源提供、远程资源仓库、自动下载补全暂不实现；不存在默认联网兜底。
- 创作者工具使用用户提供的实际资源，不能被对战素材包的有限覆盖范围限制。对战素材包也不替代任意地图／Mod 的资源依赖。

上表是目标包边界，不要求一次创建。`sc2-observer` 在本文专指无头观战管理，不是游戏客户端采集器。

### 3.2 依赖原则

```text
WhiteoutLib WASM → 模型预览器的低层适配与 TS 数据／渲染能力
                          ↑
                  地图预览器按需复用

录像组件 ────────────────┐
SC2 客户端 → main 采集适配 ├→ replay-parser → 无头观战器 → 文字界面（先交付）
                        ┘                     ├→ 2D 观战渲染器 ← 2D 素材包
                                              └→ 3D 观战渲染器 ← 3D 素材包
```

- 预览器各自是一个独立包，可使用公开子入口导出解析、运行时和控制器；不先拆出大量共享空包。
- 观战器不依赖模型／地图预览器或任一渲染器，不导入 Vue、Pinia、Three.js、DOM、Node 文件系统或 Electron。
- 2D / 3D 观战渲染器必须单独发布和按需加载，不因选择 2D 而加载 3D 模型及其素材。
- 3D 场景未来可复用预览器公开的模型、地图能力；是否直接依赖及具体子入口，在文字观战验收后按性能与耦合验证确定，不作为前期强制前置条件。
- 类型从所属包公开导出；不在应用共享类型中复制整套工具链契约，不跨包导入源码。
- 公共资源读取接口以调用方注入的异步字节读取为边界；只有出现稳定的多个实际消费者后才讨论抽取共享包。

## 4. 模型预览器

### 4.1 WhiteoutLib 使用方式

WhiteoutLib 只作为底层格式和解码能力来源。固定上游仓库、commit、构建选项、WASM 摘要和许可证；不在运行时拉取最新构建，不把上游生成的 TS 包当作本项目公共 API。

本项目实现：

- WASM 初始化、任务取消、错误转换和资源释放。
- 自有 TS 类型、模型中间数据及批量转换。
- 材质、动画、实例、附件点、相机、选择和预览控制器。
- 外部资源解析、缺失能力诊断、缓存及公开 API。

允许使用必要的上游 Embind／低层桥接；公共接口不泄露其对象、指针或内存生命周期。现有绑定逐字段访问成本过高时，先验证批量导出桥接，不逐顶点跨 WASM 边界。

自有数据包括顶点／索引／子网格 TypedArray、骨骼与绑定矩阵、动画轨道与序列、材质层、纹理引用、附件点、包围体及不支持特性清单。长期持有的数据归属必须明确，避免 WASM 内存增长或释放使视图失效。

### 4.2 功能与兼容性

首个可用版本覆盖打开模型、资源关联、相机、播放／暂停／动画定位、队伍颜色、附件点／骨骼／包围体显示及缺失资源提示。M3 复杂混合材质、粒子、ribbon、补充动画等逐项建设，能力报告区分“可解析”和“可正确渲染”。

Three.js + WebGL2 作为首轮渲染候选，不预设标准 PBR 材质足以还原 M3；特殊材质、透明排序和队伍颜色需单独实现与对照。WebGPU 不作为首版必要条件。

参考分工：WhiteoutLib 用于格式；mdx-m3-viewer 用于资源与实例组织、M3 表现研究；star-tools-three-m3-loader 用于 Three.js 模型／动画／附件点流程。引用或移植代码保留来源和许可，不假定参考项目已经覆盖全部 M3 特性。

## 5. 地图预览器

同一地图数据支持 2D 与 3D，复用资源依赖、坐标、选择和相机定位语义，不强制两种模式复用所有绘制代码。

- 地图读取支持归档及组件目录，按阶段实现 MapInfo、高度、精细高度、地表纹理蒙版、悬崖／坡道、Objects、道路、水面与其他场景层。
- 借鉴 OpenRealm 的格式与地形算法，在本项目实现 TS 解析与浏览器渲染；不整体移植其游戏服务器、Galaxy VM、菜单或原生 SDL 窗口。
- 资源解析显式处理基础游戏、依赖 Mod、地图覆盖与版本。地图包通常不包含全部模型和纹理，缺失资源不得靠其他版本静默补齐。
- 2D 可先显示地图内置小地图与场景标记，后续生成校准过的高清分块俯视图；标明底图质量，不将小地图当作精确地形数据。
- 3D 显示地形与静态放置物，逐步提高材质、光照与模型还原；静态预览不运行完整脚本，不保证开局脚本生成物存在。
- 固定地图原点、全图尺寸、可玩边界、Y 轴方向、世界与像素转换，提供坐标对照测试。
- 单独预览地图时的原始放置单位，与观战中的动态单位分层；接入录像后不能把出生对象重复绘制两次。

## 6. 在现有 parser 中完善精确状态

### 6.1 精确状态来自哪里

继续维护现有解码能力，并在同一个 parser 包中提供空间事件与采集状态的纯数据规范化、校验、来源和版本契约。**parser 不启动游戏，不承担协议连接或安装资源读取。**

```text
app-main 的受控采集任务
  → 匹配版本的 SC2 客户端
  → 官方 API start_replay / step / observation
  → parser 的采集状态规范化入口
  → 带证据和时间索引的观战数据
```

不另建精确模拟器包。客户端进程、WebSocket、文件读取、采集队列、缓存持久化及取消属于 main 适配层；parser 接受字节或纯数据，可在浏览器使用，不依赖 Node 或 Electron。

### 6.2 两类来源不能混称

| 来源               | 可承诺内容                                     | 不能承诺                                     |
| ------------------ | ---------------------------------------------- | -------------------------------------------- |
| 录像事件解码       | 有证据的出生、死亡、类型／归属变化、稀疏位置等 | 所有单位连续真实轨迹                         |
| 原版客户端状态采集 | 对应版本引擎模拟后、API 实际提供的采样状态     | 完整引擎内部状态、全部视觉事件或任意视角字段 |

官方 raw API 对敌方、迷雾快照等字段有限制。先实测全局观察、玩家视角、潜地／隐形、运输、变形和短暂效果；禁用迷雾不自动意味着所有订单、动画和内部字段均可得。缺失值保留未知，不补零；单位不在观察列表中不等于死亡。

### 6.3 契约要求

- 保留 `gameLoop` 原始时间；速度与实际时间转换单独声明，沿用并核对现有时间基准，不统一硬编码所有版本为 16 或 22.4。
- 元数据记录录像 hash、baseBuild／实际运行版本、地图与依赖身份、parser 算法、采集配置和能力覆盖。
- 单位身份无损：tracker index＋recycle 与 raw uint64 tag 分别保留；没有经验证的映射不强行拼接。raw tag 不进入不安全的 JS number，内部可映射紧凑 ID。
- 状态包括按能力可得的位置／朝向、存活、类型、归属、血盾能量、建造进度、buff、订单和动态地图层；每类字段保留可用性及来源。
- 全局与玩家视角分开标识。仅有全局状态时，不宣称能够还原玩家当时所见。
- 事件记录观测时间精度：步长大于一 loop 时，首次发现变化不等于真实发生 loop。逐 loop 采集仍不代表 API 可提供所有视觉事件。
- 跳过、缺口、未知版本、取消与采集中断都有明确状态；不通过平滑插值掩盖采集缺失。

### 6.4 采集策略

先验证非 realtime 模式按 loop 推进。每 loop 采集作为精确状态候选；2～4 loops 等配置作为降本采样候选，最终档位由真实测试决定。画面插值只用于表现，不把采样结果宣称为逐 loop 真值。

首次采集需推进原版录像，不能假定瞬间跳到任意时刻。已缓存部分可立即定位；未采集部分显示进度。首版“实时观战”指录像边采集边观看，不包括正在进行的 Battle.net 对局接入。

## 7. 无头观战器与文字优先交付

### 7.1 核心职责

无头观战器只消费 parser 的公开观战数据契约和注入的数据源，不接管解析原始录像或采集客户端。提供：

- 会话加载／卸载与能力查询。
- 播放、暂停、倍速、定位、步进、播放时钟。
- 分块预取、已采集边界、缓冲、取消、错误及恢复。
- 单位选择／跟随目标、玩家／队伍／视角状态。
- 按时间查询单位、资源、生产、损失与分析标记。
- 订阅与取消订阅；卸载后释放缓存和任务。

内部区分播放意图、缓冲状态和当前可用时间范围。异步定位采用任务序号／取消，旧请求不能覆盖新请求。跳转从关键帧重建，不依赖把整场从头播放。

不依赖真实墙钟定时器才能工作：时钟可注入，支持确定性步进测试。渲染器拿到只读的当前状态与增量，不另建独立播放时钟、统计或分析口径。

### 7.2 客户端先以文字使用

在录像分析界面增加文字观战入口，先验收：

- 录像／地图／版本、来源与能力覆盖。
- 当前时间、采集进度、播放／暂停、速度、时间定位。
- 玩家概览和当前单位列表：身份、位置、类型、归属、存活及可得状态。
- 所选单位详情、事件列表和已有分析指标的时间联动。
- 缺失字段、部分覆盖、未采集区间与失败反馈。

页面在 1000×700 标准主窗口验收，单位列表分页／虚拟化，不把全量单位状态放入深度响应式树。界面和操作提示遵循现有 Nuxt UI 与三语言规范。

文字观战必须调用真正的无头包，不在页面临时实现第二套播放逻辑。无需模型、地图预览器或任一素材包即可使用，先证明状态和定位正确。

## 8. 独立 2D / 3D 观战场景渲染器

两个包共享无头观战器的时间、选择、视角与分析，不共享隐式全局状态。统一交互语义：挂载／释放、尺寸变化、读取当前状态、相机定位、拾取和选择反馈；准确 API 在文字阶段数据契约稳定后定义。

- **2D**：分块地图背景、单位图标／方向动画精灵、血条／选择圈、轨迹、范围、迷雾／菌毯及分析覆盖。以 GPU 批处理为优先候选，不能默认逐单位 Canvas2D 就足够。
- **3D**：地形、模型实例、朝向、队伍颜色、动画、光照和逐步补齐的技能表现。状态驱动动画和推断表现必须区分，不把推断特效作为分析证据。
- 缺少素材时使用清晰的占位符并保留单位类型与选择能力；不丢掉单位、不影响 headless 查询。
- 两种模式切换不重新解析／采集或重算公共分析；保留时间、选择和地图目标位置，允许各自相机表现不同。
- 同一时刻只保留必要的活跃渲染资源；不为切换方便无条件常驻两套大型 GPU 场景。

## 9. 对战常用单位素材包

### 9.1 两个包独立发布

- **2D 素材包**：图标、按需多方向／多动画精灵图、图集与定位元数据。
- **3D 素材包**：选定模型、纹理、动画及运行所需依赖，具体分发格式由浏览器性能测试确定。
- 分开下载／加载和版本化；不用 2D 包依赖完整 3D 包来生成运行时精灵。
- 以明确清单界定对战常用单位，分阶段涵盖建筑、资源、形态与必要的表现依赖；首版名单、分辨率和动画覆盖另行确认，不扩展为全游戏素材。
- 合作、战役和自定义地图默认不在覆盖承诺内；使用占位或用户主动提供的资源，不静默下载。

### 9.2 清单与兼容性

资源清单记录稳定资源键、适用游戏版本／单位映射、变形或皮肤变体、依赖、内容摘要、尺寸／方向／动画范围、坐标约定、来源与授权。单位 numeric ID 按版本映射，不全版本写死；不能简单用显示名称找文件。

使用相同资源键关联 2D／3D，不要求二者完全相同的覆盖率；运行时查询能力。缓存按内容摘要和处理流水线版本失效，不能只按文件名复用。

### 9.3 发布门槛

本节记录产品期望，**不构成已取得素材分发权的声明**。WhiteoutLib 的 BSD、其他代码的 MIT 或自行烘焙均不自动授予暴雪素材再分发权。

发布前逐项确认许可／授权依据、转换及再分发限制、署名和来源，并更新第三方声明；未经确认的素材不得随应用、npm 包或下载服务发布。授权未满足时仍可发布工具代码，素材包保持未发布，使用用户本地合法资源完成本地验证，不把“仅对战用途”当作授权替代。

## 10. 性能、缓存与安全

- 对外 TS API，浏览器入口不导入 Node／Electron。Vue 仅存在于应用适配，不进入可复用包。
- 解析、WASM 转换、分块解码和压缩进入 Worker／桌面 worker，使用 TypedArray、Transferable 和有界队列。
- WASM 生命周期、GPU 纹理／网格、Worker、订阅、资源 URL 都有确定释放路径；重复打开／关闭验证无持续增长。
- 大量相同单位共享网格、纹理、材质；骨骼动画的批处理、LOD、阴影开销独立测量，不默认每单位一棵复制骨架可以扩展。
- 观战缓存采用版本化索引、关键帧和分块增量，不用整场巨大 JSON。主进程管理文件与提交，parser 提供纯数据格式处理，headless 通过注入源按需读取。
- IPC 传输有界窗口／分块，不逐帧请求所有坐标；避免直接沿用当前分析结果大小限制传输整场观战数据，应单独定义契约与预算。
- 资源读取、解压、纹理尺寸、顶点／骨骼数、递归依赖和并行任务均设预算；路径规范化与目录边界在 host 校验，未知资源不执行脚本。
- Electron 不降低 contextIsolation 或暴露任意文件／channel；浏览器资源仅读取本次用户提供的内容，不自动上传。
- 性能基准记录设备、GPU、窗口、单位数、地图、采样档位、帧耗时分位、峰值内存、定位延迟、采集耗时和缓存体积。60 FPS 为待验证目标，不承诺任意地图／单位规模均达到。

## 11. 实施顺序与验收

| 阶段                  | 交付                                                             | 验收门槛                                                                     |
| --------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| P0：并行可行性验证    | WhiteoutLib 构建与 TS 转换；原版客户端采集样本                   | 上游版本固定；真实模型可核对；对战与合作分别记录 API 能力、缺失及采集成本    |
| P1：模型工具          | 独立模型预览器与创作者入口                                       | 桌面拖入／本地实例；浏览器拖入；动画材质对照、缺依赖和释放测试               |
| P2：地图工具          | 独立地图预览器与创作者入口                                       | 代表地图的 2D / 3D、坐标对齐、依赖覆盖、缺层诊断；不夸大完整格式支持         |
| P3：parser 与文字观战 | parser 状态契约、main 采集适配、独立 headless 包、客户端文字界面 | 无图形依赖可运行；步进／定位／取消稳定；采集状态与原版对照；身份和视角可验证 |
| P4：2D 观战           | 独立 2D 渲染器；经授权的 2D 素材包或本地素材                     | 共用 P3 时间与分析；常用单位清单、缺素材降级、GPU 性能验收                   |
| P5：3D 观战           | 独立 3D 渲染器；经授权的 3D 素材包或本地素材                     | 同状态跨模式对照；视觉误差清单、批量动画与显存、切换释放验收                 |

P3 必须先于 P4／P5；P0 的状态采集验证不得拖到图形阶段。P1／P2 是独立创作者工具，可与 P3 按人员与资源并行，不应因其未完成阻塞文字观战。正式素材发布依赖授权，不阻塞代码包和本地资源验证。

测试包括纯数据单元测试、确定性时钟与定位测试、异常／中断／缺块测试、真实录像对照、代表模型／地图图像回归、桌面与浏览器资源入口及性能压力测试。合成样本通过不等于真实地图或全版本兼容。

后续实施前仍需确认的细节：发布包名、常用单位素材首版清单与授权、支持的游戏版本／地图范围、采样档位、参考设备和量化性能阈值。它们不改变本文已确认的包边界。

## 12. 调研依据与限制

以下是 2026-11-06 调研入口，均是外部项目当时状态的参考，不表示已在本地构建或完整验证。实施时固定 commit、核对许可与兼容性，不仅依赖可变 README。

- [WhiteoutLib，sc2-arcade-watcher 分支](https://github.com/sc2-arcade-watcher/WhiteoutLib)：底层模型／纹理／存储及 WASM；[实际 WASM 绑定目录](https://github.com/sc2-arcade-watcher/WhiteoutLib/tree/libmodkit/bindings/wasm)。根 README 的 TS 路径与调研时目录不完全一致，必须以实际构建产物验证。
- [mdx-m3-viewer](https://github.com/flowtsohg/mdx-m3-viewer)：MIT，M3 部分支持、声明不再积极维护；其魔兽地图支持不等于 SC2 地图支持。
- [star-tools-three-m3-loader](https://github.com/sc2-arcade-watcher/star-tools-three-m3-loader)：MIT，Three.js M3 模型、动画、附件点与导出参考。
- [StarMods 地图库](https://starmods.space/gallery/starcraft-2/map)：已观察到实际 SC2 地形预览；完整地图渲染器的公开源码和许可尚未确认，不直接复制网站脚本。
- [OpenRealm SC2 状态](https://github.com/corepunch/open-realm/blob/main/docs/games/starcraft-2/readme.md)：MIT，地形／模型原型；不是完整 SC2 引擎或已完成录像重演器，Web 构建不能自动推导为 SC2 已支持。
- [官方 SC2 API](https://github.com/Blizzard/s2client-proto/blob/master/s2clientprotocol/sc2api.proto)及 [raw 状态定义](https://github.com/Blizzard/s2client-proto/blob/master/s2clientprotocol/raw.proto)：启动录像、步进、观察与字段可见性约束。
- [sc2reader tracker 实现](https://github.com/ggtracker/sc2reader/blob/upstream/sc2reader/events/tracker.py)：位置事件稀疏，不能视作全单位逐帧快照；目标 build 仍需实测。
- [Vespene](https://vespene.gg)：产品体验参考，不作为已确认开源依赖；其部分实现描述来自 [sc2tools 的研究文档](https://github.com/ReSpOnSeSC2/sc2tools/blob/main/docs/replay-animation-research.md)，不应当作本项目已验证能力。
